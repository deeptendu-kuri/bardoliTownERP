# 07 — AI Integration

**Scope:** every AI feature, how it calls the Claude API, the prompts/IO contracts, models,
cost, and the human-in-the-loop guardrails. All AI runs server-side in the `ai-suggest` /
`weekly-summary` Edge Functions. AI features are **phase 2** (PRD §6) — the MVP "who's free"
prompt is rules-based, not AI.

---

## 1. Principles
- **Suggest, never act.** AI output is always a suggestion the admin/CEO accepts or dismisses;
  nothing transitions a task or assigns a person automatically.
- **Server-side only.** The `ANTHROPIC_API_KEY` lives in Edge Function secrets; the browser
  never sees it or calls Anthropic directly.
- **Grounded.** Prompts include only the structured studio data needed (skills, occupancy,
  recent task history) — no fabricated context. Log every suggestion to `ai_suggestions`.
- **Cheap by default.** Use the smallest model that does the job.

## 2. Models (verify current strings at https://docs.claude.com/en/docs/about-claude/models)
- Suggestions (assignment, load, deadline, lead scoring): `claude-haiku-4-5-20251001` — fast/cheap.
- Weekly summary (more nuanced synthesis): `claude-sonnet-4-6`.
- Keep `max_tokens` tight; request **JSON-only** output and parse defensively.

## 3. Features
### 3.1 Flow-based assignment (the operator's core idea)
Given a project task to assign and the free-now candidates, suggest the person who recently did
the most similar work (same `video_type`/industry) so they stay in flow.
- **Input context:** the task (type, project video_type, client industry), candidate profiles
  (skills, current load from `v_occupancy`), each candidate's last N completed task types.
- **Output:** `{ assignee_id, rationale }`. Admin sees it in an `AISuggestionCard`; Accept calls
  the normal `assign_task` RPC.

### 3.2 Load balancing
Flag when one person is overloaded while another is idle; propose a fairer split. Input: full
`v_occupancy`. Output: `{ moves:[{task_id,from,to,reason}] }` — admin confirms each.

### 3.3 Deadline-risk
Compare a task's estimate to the assignee's historical estimate-vs-actual to warn when an upload
date is likely to slip. Output: `{ risk:'low'|'med'|'high', reason }` shown on the task.

### 3.4 Lead prioritisation
Score open leads by warmth (stage, recency, requirements richness) so the admin follows up with
the likeliest closes first. Output: `{ ranked:[{client_id, score, reason}] }`.

### 3.5 Weekly auto-summary (CEO)
A Monday digest: what shipped, what's stuck, who's stretched, revision hotspots. Generated by a
scheduled call to `weekly-summary`, stored, and surfaced on `/overview`.

## 4. Edge Function shape (`ai-suggest`)
```ts
const res = await fetch('https://api.anthropic.com/v1/messages', {
  method:'POST',
  headers:{ 'content-type':'application/json',
            'x-api-key': Deno.env.get('ANTHROPIC_API_KEY')!,
            'anthropic-version':'2023-06-01' },
  body: JSON.stringify({
    model: 'claude-haiku-4-5-20251001',
    max_tokens: 600,
    system: SYSTEM_PROMPTS[type],          // role-specific, demands JSON-only
    messages: [{ role:'user', content: JSON.stringify(context) }],
  }),
});
const data = await res.json();
const text = data.content.map((c:any)=>c.type==='text'?c.text:'').join('');
const suggestion = JSON.parse(stripFences(text));   // defensive parse; reject on failure
```
Always: validate JWT + admin role, validate `context` with zod, log to `ai_suggestions`, return
`{ ok, data:{ suggestion, rationale } }`. On parse failure, return `ok:false` (UI falls back to
the rules-based prompt — AI is never load-bearing).

## 5. Prompt rules
- System prompt states the role ("You suggest the best assignee…"), the exact JSON schema, and
  "return only JSON, no prose, no markdown fences."
- Never include secrets or unrelated PII. Include only IDs + the minimal attributes needed.
- Keep prompts in `supabase/functions/ai-suggest/prompts.ts`, versioned and unit-testable.

## 6. Cost & safety
- Suggestions are on-demand (admin clicks "Suggest") + the weekly cron — not per keystroke.
- Cache identical suggestion requests briefly. Track token usage per call in logs.
- Degrade gracefully: if the API is down or returns bad JSON, the admin still has the rules-based
  "who's free" prompt and full manual control.
